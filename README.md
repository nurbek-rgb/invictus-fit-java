# Invictus Fit — Research және талаптар

## 1. Жоба туралы

Invictus Fit — фитнес-клубтағы жаттығуларға жазылуды, бос орындарды
бақылауды және пайдаланушыларға автоматты хабарландыру жіберуді
ұйымдастыратын Java оқу жобасы.

Негізгі идея — қатысушыға, жаттықтырушыға және әкімшіге өздеріне
қатысты өзгерістер туралы ақпаратты уақытында жеткізу.

Жоба жеке (соло) орындалады. Демонстрациялық деректер пайдаланылады.
Бұл құжат жоспарланған талаптарды сипаттайды.

## 2. Негізгі мәселе

Жаттығудағы орындар толған кезде қатысушы бос орынның пайда болуын
қолмен тексеруге мәжбүр болуы мүмкін. Басқа қатысушы жазылудан бас
тартқанын уақытында білмесе, ол бос орынға жазылу мүмкіндігін өткізіп алады.

Жаттықтырушыға қатысушылар санының өзгеруі, ал әкімшіге жаттығулардың
толуы және кестедегі өзгерістер туралы ақпарат қажет.

Ақпаратты тек қолмен тексеру:

- Қатысушының уақытын алады.
- Бос орын туралы кеш білуге әкелуі мүмкін.
- Жаттықтырушының қатысушылар тізімін бақылауын қиындатады.
- Әкімшіге жаттығулардың жүктемесін қадағалауды қиындатады.

Бұл — оқу жобасында шешілетін мәселе. Нақты Invictus клубының
қолданыстағы жүйесінде осындай кемшілік бар деген тұжырым жасалмайды.

## 3. Жобаның мақсаты

Жаттығулардағы бос орындардың күйін бақылап, маңызды өзгерістер
болғанда Member, Trainer және Admin рөлдеріне сәйкес автоматты
хабарландыру беретін жүйе әзірлеу.

## 4. Ұсынылатын шешім

Жүйе әр жаттығудың сыйымдылығын және жазылған қатысушылар санын сақтайды.

Орындар күйі:

- AVAILABLE — бос орын бар.
- FULL — барлық орын толған.
- CANCELLED — жаттығу өткізілмейді.

Орын болмаған жағдайда қатысушы күту тізіміне қосыла алады.
Орын босаған кезде жүйе күту тізіміндегі қатысушыларға хабарлама жібереді.

Хабарлама автоматты түрде жазылды дегенді білдірмейді.
Қатысушы жазылуды өзі растайды, ал жүйе бос орынды қайта тексереді.

Бастапқы нұсқада хабарламалар бағдарлама ішінде көрсетіліп,
деректер қорында сақталады. Email, SMS және мобильді push
хабарламалары бөлек кеңейту ретінде қарастырылады.

## 5. Рөлдер және хабарландырулар

| Рөл | Оқиға | Хабарлама мысалы |
|---|---|---|
| Member | Күту тізіміндегі жаттығуда орын босады | «18:00-дегі Fitness жаттығуында бос орын пайда болды» |
| Member | Өзі жазылған жаттығудың уақыты өзгерді | «Жаттығу уақыты 19:00-ге ауыстырылды» |
| Member | Өзі жазылған жаттығу тоқтатылды | «Бүгінгі жаттығу өткізілмейді» |
| Trainer | Өз жаттығуына қатысушы жазылды немесе бас тартты | «Қатысушылар тізімі жаңартылды: 14/15» |
| Trainer | Өз жаттығуындағы орындар толды | «Жаттығуыңыздағы барлық орын толды: 15/15» |
| Admin | Жаттығу толық күйге өтті | «18:00-дегі жаттығу толық: 15/15» |
| Admin | Толық жаттығуда орын босады | «18:00-дегі жаттығуда бос орын бар: 14/15» |
| Admin | Кесте өзгертілді немесе жаттығу тоқтатылды | «Жаттығулар кестесі жаңартылды» |

Қатысушы кестеден барлық жаттығудың бос орын санын көре алады.
Жеке хабарламалар тек өзіне қатысты оқиғалар бойынша жіберіледі.

## 6. Негізгі жұмыс сценарийі

1. Жаттығудың сыйымдылығы — 15 адам.
2. 15 қатысушы жазылғаннан кейін жаттығу FULL күйіне өтеді.
3. Тағы бір қатысушы күту тізіміне қосылады.
4. Жазылған қатысушылардың бірі жазылудан бас тартады.
5. Жүйе бос орын санын қайта есептейді: 1 орын.
6. Жаттығу AVAILABLE күйіне өтеді.
7. Күту тізіміндегі қатысушыларға бос орын туралы хабарлама келеді.
8. Жаттықтырушы мен әкімші өз рөлдеріне сәйкес хабарлама алады.
9. Қатысушы жазылуды растаған кезде жүйе орынды қайта тексереді.
10. Орын әлі бос болса, жазылу сақталып, қатысушы күту тізімінен алынады.

Бірнеше қатысушы бір уақытта жазылса, соңғы бос орынға тек бір
жазылу қабылдануы керек.

## 7. Функционалдық талаптар

- FR-01: Member, Trainer және Admin рөлдерін қолдау.
- FR-02: Жаттығулар кестесін және бос орын санын көрсету.
- FR-03: Жаттығуға жазылу және жазылудан бас тарту.
- FR-04: Орын санынан артық жазылуға жол бермеу.
- FR-05: Бір жаттығуға қайталап жазылуды болдырмау.
- FR-06: Толық жаттығудың күту тізіміне қосылу және одан шығу.
- FR-07: Күту тізіміне қайталап қосылуды болдырмау.
- FR-08: Орын босағанда күтіп жүрген қатысушыларды хабардар ету.
- FR-09: Жаттықтырушыға өз жаттығуларындағы өзгерістерді хабарлау.
- FR-10: Әкімшіге жаттығулардың толуы мен орын босауын хабарлау.
- FR-11: Кесте өзгергенде тиісті пайдаланушыларға хабарлама жіберу.
- FR-12: Хабарламаларды сақтау және оқылды деп белгілеу.
- FR-13: Бір оқиға туралы бір пайдаланушыға қайталанған хабарлама жасамау.
- FR-14: Жаттығулардың толуы туралы есепті CSV файлына экспорттау.

## 8. Міндетті технологиялар

| Технология | Жобада қолданылуы |
|---|---|
| ООП | User базалық класы; Member, Trainer, Admin туынды кластары; инкапсуляция және полиморфизм |
| Интерфейстер | NotificationService арқылы хабарландыру логикасын бөлу |
| Коллекциялар | List — жаттығулар мен хабарламалар; Set — қайталанбайтын алушылар; Map — ID бойынша іздеу |
| Generics | Ортақ Repository<T> интерфейсі |
| Stream API | Бос орны бар жаттығуларды сүзу және толу деңгейі бойынша есеп дайындау |
| SQLite + JDBC | Пайдаланушыларды, жаттығуларды, жазылуларды және хабарламаларды сақтау |
| Файлдар | Есептерді CSV форматына экспорттау |
| Көпағындылық | ExecutorService арқылы хабарламаларды фондық өңдеу |
| Maven + JUnit | Жобаны жинау және бизнес ережелерді тестілеу |
| GitHub | Код, құжаттама және өзгерістер тарихын сақтау |

## 9. Деректер қорының негізгі кестелері

| Кесте | Мақсаты |
|---|---|
| users | Пайдаланушылар және олардың рөлдері |
| workouts | Жаттығу, жаттықтырушы, уақыт және сыйымдылық |
| bookings | Қатысушылардың жаттығуларға жазылуы |
| waitlist | Бос орын күтіп жүрген қатысушылар |
| notifications | Хабарлама алушысы, мәтіні, оқиға түрі және оқылу күйі |

bookings және waitlist кестелерінде пайдаланушы мен жаттығу жұбы
қайталанбауы керек.

Жазылу кезінде орынды тексеру және жазуды сақтау бір транзакцияда
орындалады. Хабарландыру тек өзгеріс сәтті сақталғаннан кейін жасалады.

## 10. Сенімділік талаптары

- Қатысушылар саны жаттығу сыйымдылығынан аспауы керек.
- Пайдаланушы тек өз хабарламаларын көруі керек.
- Өзгермеген күй туралы қайта-қайта хабарлама жіберілмеуі керек.
- Хабарламалар бағдарлама қайта ашылғанда сақталуы керек.
- Фондық өңдеудегі қателер тіркеліп, өңделуі керек.
- Әр фондық тапсырма деректер қорымен қауіпсіз жұмыс істеуі керек.
- Бағдарлама жабылғанда фондық тапсырмалар дұрыс аяқталуы керек.

## 12. Орындау кезеңдері

1. Research және талаптар тізімін дайындау.
2. Use Case, Class, Sequence диаграммаларын және ДҚ схемасын жасау.
3. MVP: кесте, бос орындар, жазылу және бас тарту.
4. Күту тізімі мен рөлге сәйкес автоматты хабарландыруларды қосу.
5. Stream API есептері, CSV экспорты және фондық өңдеуді қосу.
6. Тесттерді орындау, қателерді түзету және README дайындау.
7. Жұмыс сценарийлерін демонстрациялау және жобаны қорғау.

## 15. Қалай бастау керек

1. **Құралдар:** JDK 21+, IntelliJ IDEA, Maven, JUnit 5. Алдымен консольдық нұсқа.
2. **Enum-дар:** `ClassCategory` (CARDIO, MIND_BODY, STRENGTH, FUNCTIONAL, DANCE), `Level` (EASY, MEDIUM).
3. **Класстар:** `Membership` (abstract) → `AnnualMembership`, `TrialMembership`, `MonthlyMembership`; сосын `Member`, `Trainer`, `GroupClass`, `Visit`, `Schedule`.
4. **Тест деректері:** 7 клуб, 3–4 тренер, 8–10 сабақ.
5. **Ережелер:** мерзімі өткен абонементпен кіргізбеу; сабақ толса `ClassFullException`; Trial-да `visitsLeft` азайту.
6. **Консольдық меню:** мүше тіркеу, абонемент сатып алу, сабаққа жазылу, кіруді тіркеу, кестені көру.
7. **Тест және сақтау:** JUnit тесттері, кейін CSV/JSON файл немесе SQLite.
